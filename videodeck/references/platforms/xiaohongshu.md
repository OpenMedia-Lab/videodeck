# Xiaohongshu

Follow the [publication contract](../publishing.md). Use current
[xhs-cli](https://github.com/OpenMedia-Lab/xhs-cli) help and its video-publishing
contract for upload, processing, dry-run, readback and original-ID edits.

## Platform version before confirmation

Read current [official community rules](https://agree.xiaohongshu.com/h5/terms/ZXXY20221213003/-1)
and any actual account moderation notice. Check the served document's revision
date; a page retrieved today is not necessarily a newly issued policy.
Check title/body, cover, visible source labels/closing cards, subtitles and speech.
External URLs and invitations to another platform can be classified as outbound
guidance even for the author's own technical article. Use neutral author/work-title
attribution for the platform version and remove
outbound calls and contact routes. Split links, QR codes, search hints and vague
invitations can retain the same outbound intent; evaluate them against the actual
notice rather than assuming that less explicit wording is approved. Preserve
technical source titles and project names when they explain the material.

If approved narration contains an outbound call, identify its exact segment and
resolve the allowed audio change. Preserve the accepted voice and technical
explanation; update the matching captions. A body-only fix leaves other channels
unchanged. Final confirmation includes native topic entities and visible markers,
activity, visibility and any native content declaration.

## Submission and recovery

Keep reusable material receipts and a durable submission/edit journal. Verify
native topics, the separate activity relation and requested declaration along
with the generic media/copy readback.
File IDs can become canonical IDs; use the CLI's original-media fingerprint
verification and retain its evidence, rather than editing the original payload
until IDs match. Report explicit body-format normalization separately from exact
text equality.

Read `my-notes` punishment/advice fields as well as creator detail and public feed;
enabled/public/readable can coexist with restricted recommendation or search.
For a restricted note, inspect its actual reason before preparing an in-place edit
and query these fields again afterward. Distinguish correction accepted, punishment
marker absent, future reach, effective activity count and rewards.
